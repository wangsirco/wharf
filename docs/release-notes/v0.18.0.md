**Wharf 码头 0.18.0 — proxy extension and dynamic DNS · 代理扩展与动态域名**

### Install / upgrade · 安装与升级
Panels on 0.17 show this update in the top bar (*Settings → Version & updates*). New installs:
0.17 的面板会在顶栏提示更新（「系统设置 → 版本与更新」）。全新安装：
```sh
opkg install /tmp/luci-app-wharf_0.18.0-1_<arch>.ipk
```

### Proxy extension · 代理扩展
Run proxy nodes on the router itself, for you and your friends — no extra Linux box or panel.
在路由器上直接搭代理节点，给自己和朋友用，不用再另开一台 Linux 装面板。

- **Official Xray, your choice of version.** Installed online from XTLS/Xray-core releases and checked against their SHA-256; stable or pre-release; every configuration is checked by Xray before it goes live, and a core that fails to start is rolled back. Runs as `nobody`, never touches the xray of PassWall / OpenClash, and is removed with the panel.
  **官方 Xray，版本自选。** 从 XTLS/Xray-core 官方 Release 在线安装并校验；配置先经 Xray 检查再生效，启动失败自动回退；以 nobody 运行，不碰其他插件的 xray，随面板卸载。
- **Protocols.** VLESS + REALITY + Vision / XHTTP, VLESS + TLS (Vision, WebSocket, gRPC, HTTPUpgrade, XHTTP), Trojan, VMess, Shadowsocks 2022, Hysteria 2.
  **协议**：REALITY、XTLS Vision、XHTTP、Trojan、VMess、SS2022、Hysteria 2。
- **Firewall linked.** A node opens its port with a standard redirect and goes through the same conflict checks as port forwards; nodes appear in the forwards list.
  **防火墙联动**：建节点即放行端口、做冲突检查，并出现在端口转发列表里。
- **Shared 443 by SNI.** Nodes share public 443 with a camouflage website. If 443 already forwards to your website (1Panel, nginx …), the forward stays exactly as it is: Cloudflare traffic goes straight through, everything else that is not for a node is handed to the same server from the visitor's own address, so the site still sees real visitors. Optional read-only 1Panel API link lists its websites and keeps node names clear of them.
  **443 按域名分流**：多个节点共用 443，陌生访问看到伪装网站。443 已经转发给网站（1Panel、nginx 等）时，原转发一条不改：Cloudflare 回源直达，其他不是节点的访问以访客自己的 IP 转给原服务器，网站看到的仍是真实访客。可选连接 1Panel API（只读），列出网站并避免域名冲突。
- **Shared port, your choice.** 443 by default; switch to 8443, 2053 … when your provider blocks 443 or 443 belongs to another service. Certificates are then self-signed and pinned in the links (Let's Encrypt only validates on 443).
  **分流端口可选**：默认 443；运营商封了 443、或 443 要留给别的服务时，可换成 8443、2053 等。换端口后证书改用自签并在链接里带指纹（Let's Encrypt 只在 443 上验证）。
- **fw4 / nftables too.** The shared-port split and the transparent hand-off also work on fw4 routers (OpenWrt 22.03+ defaults), in a table of their own that fw4 reloads leave alone. Not yet tested on hardware — reports welcome.
  **也支持 fw4 / nftables**：共用端口与透明转发在 fw4 路由器（OpenWrt 22.03 起的默认防火墙）上同样可用，规则放在独立的表里，fw4 重载不受影响。尚未实机测试，欢迎反馈。
- **No more blank pages.** A page that fails to render shows the error with Retry / Reload and logs it on the router (`logread | grep "ui error"`); fixed the proxy settings tab going blank before 1Panel was connected.
  **不再白屏**：页面出错时显示原因并可重试，错误写入路由器日志；修复未连接 1Panel 时代理「扩展设置」白屏。
- **Fix · 修复**: on devices that do not trust the panel's certificate, the panel could keep showing "无法连接面板" after the first visit. The service worker that caused it removes itself. · 不信任面板证书的设备在首次访问后可能一直显示「无法连接面板」，已修复。
- **Certificates.** Let's Encrypt via TLS-ALPN on 443 (no port 80), or self-signed with fingerprint pinning (Xray 26 `pcs`).
  **证书**：自动申请 Let's Encrypt（不需要 80 端口），或自签证书 + 指纹校验。
- **Users.** Traffic limits with monthly reset, expiry, simultaneous-IP limits, no LAN access by default, links, QR codes and subscriptions.
  **用户**：流量上限与每月清零、到期、同时在线 IP 限制、默认禁止访问局域网、链接 / 二维码 / 订阅。
- **Big screen and records.** Live rates per node and user, usage trends, who is online from where, and per-user access records (what was reached, from which address).
  **大屏与记录**：每个节点和用户的实时速率、用量趋势、谁在线、从哪里来，以及每个用户的访问记录。
- **Multi-admin.** New permission `proxy.manage` and quotas; admins see only their own nodes and use only their granted ports.
  **多管理员**：新权限 `proxy.manage` 与配额，管理员只能看到自己的节点、用自己的端口段。

### Dynamic DNS · 动态域名
Cloudflare, Alibaba Cloud, DNSPod, GoDaddy, Porkbun, Namecheap, DuckDNS, DynDNS protocol (No-IP, Dynu, HE.net …) and custom URLs; any subdomain depth, IPv4 / IPv6, per-WAN address detection (interface and / or public services), update on change and / or on a timer, history and alerts. CNAME records point a new subdomain at a dynamic name another device already maintains.
九类服务商、任意层级子域名、IPv4 / IPv6、按 WAN 口取地址（接口和 / 或公网服务）、IP 变化即更新和 / 或定时更新、记录与告警。家里已有别的设备做 DDNS 时，可以用 CNAME 让新子域名直接指向它。
