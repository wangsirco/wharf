适用版本：0.16 及以上 · 适用系统：OpenWrt 22.03+ / iStoreOS（x86_64、aarch64、arm）

## 1. Wharf 是什么

OpenWrt 很强，但 LuCI 只适合「一个懂网络的人」使用：

- **看不懂**：设备只显示 MAC 和 IP；流量只有总数；想知道家里某台设备在访问什么，几乎不可能。
- **不好分享**：想把一个端口段交给朋友管理，只能把 root 密码给他，他能改所有东西。
- **出事难追**：防火墙规则被谁改了、什么时候改的、原来是什么，没有记录。
- **排障靠命令行**：网络卡了，要 SSH 上去敲 mtr、tcpdump、dig，再自己解读输出。

Wharf 的目标，就是把这些变成一个「家里人能看懂、管理员敢放权、出问题有证据」的面板。

**设计原则**

| 原则 | 体现 |
|---|---|
| 只用 OpenWrt 原生机制 | 端口转发写成标准的 `firewall` redirect；地区限制用 `ipset`；DNS 统计用 dnsmasq 自带的查询日志。卸载 Wharf 后，路由器上的规则依然是标准 OpenWrt 配置，LuCI 里照样能看。 |
| 不改内核、不断网 | 所有改动只做 `reload`，从不重启网络或 WAN。 |
| 多管理员隔离 | 普通管理员只能看到、只能修改自己创建的东西；敏感操作可以要求超级管理员批准。 |
| 一切可追溯 | 每次修改都记入审计：谁、何时、从哪个 IP、原值、新值；可还原的修改支持一键还原。 |
| 数据留在家里 | IP 地理库、内容识别规则库都在本地；不依赖任何云服务。NextDNS、Proxmox、GitHub 更新检查都是可选的。 |
| 说人话 | 设备叫「爸爸的 iPhone」而不是 `5e:3a:…`；流量叫「抖音 / YouTube」而不是一串 IP；排障工具直接给结论。 |

## 3. 工作原理

```
 浏览器 / 手机 ──HTTPS──▶ owp-panel（面板：Go + SQLite + 内嵌网页）
                                 │  HMAC 签名的 HTTP API（127.0.0.1:7071）
                                 ▼
                          owp-agent（路由器代理：读写 uci / 防火墙 / conntrack / dnsmasq 日志）
                                 │
                                 ▼
                         OpenWrt（firewall、ipset、dnsmasq、conntrack、opkg …）
```

- **owp-agent**：运行在路由器上，是唯一直接操作系统的组件。所有请求必须带 HMAC 签名，默认只监听 `127.0.0.1:7071`。它每 10 秒读一次连接表、实时读 dnsmasq 查询日志，把流量按「设备 × 目标 × 端口」汇总成每分钟的记录。
- **owp-panel**：面板后端 + 网页。负责登录、权限、审计、审批、存储（SQLite）、IP 地理识别、内容识别，并把需要改动路由器的操作翻译成 agent 调用。默认监听 `7080`（HTTPS）。
- **LuCI 页面**（服务 → Wharf 码头）：开关 agent 和面板、查看入口地址、重置超级管理员密码、重置访问控制。
- **部署方式**
  - **本机模式**（默认）：agent 和面板都跑在路由器上。
  - **VPS 模式**：路由器只跑 agent（开启 HTTPS 和来源白名单），面板跑在你的 VPS 上，通过证书指纹固定连接。

**存储位置**：面板数据库与证书在 uci `owp.main.data_dir`（默认 `/etc/owp`，建议改到数据分区，如 `/mnt/data/owp`）；抓包文件在内存 `/tmp/owp-pcap`。

## 4. 安装与首次使用

### 4.1 系统要求

- OpenWrt 22.03 或更新版本（fw3 / iptables 已充分验证；fw4 / nftables 系统可安装，但部分功能仍以 iptables 方式工作）。
- 内存建议 ≥ 512 MB；面板数据库默认上限 1 GB，建议放在有足够空间的分区。
- 架构：x86_64、aarch64、arm（cortex-a7）。暂不支持 MIPS。

### 4.2 安装

```sh
# 上传到路由器后
opkg install luci-app-wharf_<版本>_<架构>.ipk
```

安装后服务自动启动。在 LuCI「服务 → Wharf 码头」里可以看到面板地址（默认 `https://路由器IP:7080`）。

**初始密码**：首次启动会生成超级管理员 `admin` 的随机密码，可在 LuCI 页面「重置超级管理员密码」获取新的。登录后请立即在右上角「修改密码」。

**升级**：直接安装新版本的 ipk 即可，配置、数据和规则都会保留。请不要使用 `opkg install --force-reinstall`（重装会触发卸载清理）。

### 4.3 浏览器提示「不安全」怎么办

面板使用自己的**本地证书**（只能用于局域网地址和 `.lan` 这类本地域名，不能用来冒充任何公网网站）。每台设备安装一次后，就不会再出现警告：

1. 在登录页底部点「浏览器提示不安全？安装面板证书」→「下载证书」。
2. 按你的系统操作：
   - **iPhone / iPad**：设置 →「已下载描述文件」→ 安装；再到 设置 → 通用 → 关于本机 → 证书信任设置，打开它的开关。
   - **Android**：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书。
   - **Mac**：双击加入钥匙串，设为「始终信任」。
   - **Windows**：双击 → 安装证书 → 放入「受信任的根证书颁发机构」。

装好后，在 iPhone 上「添加到主屏幕」的 Wharf 也能像 App 一样打开。在浏览器里输入 `http://` 地址会自动跳到 `https://`。

### 4.4 首次登录向导

每个用户第一次登录时会看到一个 5～6 步的向导，每一步都可以跳过：

1. **欢迎**：Wharf 能做什么。
2. **怎么称呼你**：填写显示名称；超级管理员还可以给面板起名字（显示在登录页、侧栏、浏览器标签和手机主屏幕图标上）。
3. **功能导览**：只显示你有权限的功能。
4. **选择样子**：简要模式（给家人）或专业模式（给折腾的人），右上角随时可切换。
5. **检查依赖组件**（仅超级管理员）：列出路由器上缺少的组件，可以一键安装，见第 5 节。
6. **准备好了**：超级管理员会看到建议的下一步（改密码、设置告警、限制公网访问、给家人开账号）。

以后可以在右上角用户菜单 →「使用向导」重新打开。

## 5. 依赖组件

Wharf 的部分功能建立在 OpenWrt 官方软件包之上。**这些包都不是强制依赖**：Wharf 没有它们也能安装和运行，缺少时对应功能会在页面顶部提示「需要安装 xxx」。

| 组件 | 软件包 | 级别 | 用于 | 缺少时 |
|---|---|---|---|---|
| conntrack 连接跟踪工具 | `conntrack` | 核心 | 流量统计、设备画像、全球流量、端口转发用量 | 没有任何流量去向数据 |
| 连接字节统计 | 内核开关 `net.netfilter.nf_conntrack_acct` | 核心 | 每个连接的字节数 | 只有连接数、没有流量大小 |
| ipset | `ipset` | 核心 | 端口转发地区 / IP 限制、设备管控、实时网速 | 这些功能不可用 |
| ip（完整版） | `ip-full` | 推荐 | 设备在线 / 离开判断 | 精简版也能用，信息较少 |
| tcpdump | `tcpdump` | 推荐 | 抓包与分析 | 抓包页不可用 |
| mtr（JSON 版） | `mtr-json` | 推荐 | 路由追踪 | 路由追踪不可用 |
| iperf3 | `iperf3` | 推荐 | iperf3 测速 | 浏览器测速仍可用 |
| dig | `bind-dig` | 推荐 | DNS 查询对比 | DNS 对比不可用 |
| curl | `curl` | 推荐 | 网站访问测试 | 网站测试不可用 |
| etherwake | `etherwake` | 可选 | 网络唤醒 | WOL 不可用 |
| UPnP 服务 | `miniupnpd-iptables` / `miniupnpd-nftables` | 可选 | UPnP 管理 | UPnP 页不可用（有安全风险，不需要就别装） |

另外，DNS 统计用的是 dnsmasq **自带**的查询日志（`logqueries`），不需要 dnsmasq-full、SmartDNS 或 AdGuard Home。使用 NextDNS 时，可以在设置里填写 API Key，看到更完整的拦截原因（可选）。

### 安装与卸载机制

- **一次装好**：在首次登录向导或「系统维护 → 依赖组件」里，勾选缺少的组件，点「安装」。面板会自动执行 `opkg update`（如需要）和 `opkg install`，并实时显示安装日志。只有超级管理员可以操作，每次操作都记入审计。
- **不捆绑**：这些都是普通的 OpenWrt 官方包，装在系统里，其他程序也能正常使用；Wharf 不会把它们打进自己的安装包，也不会修改它们的配置。
- **跟着 Wharf 一起卸载**：通过面板安装的包会记录在 `/etc/wharf-deps.list`。卸载 Wharf 时，卸载脚本会在 opkg 结束后自动移除这些包（连同只为它们装上的依赖库，`--autoremove`）。
- **不动你原有的东西**：你之前就装好的包，不会被记录，也不会被卸载。如果某个面板装的包后来被其他软件依赖了，卸载时会保留它，并在系统日志里写明原因。
- 你也可以在「系统维护 → 依赖组件」里单独移除某个「由面板安装」的组件。

## 6. 功能详解

### 6.1 简要模式与专业模式

右上角切换，按浏览器记住。

- **简要模式**：给家人看。只有一面「设备墙」和设备详情：谁在线、在用多少网速、最近 24 小时家里大多在访问什么、流量花在哪。没有任何开关，不会误操作。
- **专业模式**：完整功能。

### 6.2 概览与大屏

- **WAN 实时流量**：每 2 秒刷新，最近 5 分钟。
- **正在用网的设备**：按当前网速排序。
- **今日流量去向**：按内容大类 / 服务的环形图。
- **最近事件**：新设备加入、设备离开网络 / 回到网络（附离开时长）、WAN 掉线、定时断网生效、面板被拒绝访问、审批。
- **大屏**：`/screen`，适合放在显示器上常驻显示（含全球流量地图）。

### 6.3 网络

- 路由器每 10 秒测一次到运营商网关和几个公共目标的延迟与丢包，画成延迟曲线和可用性色带（绿 = 正常，黄 = 有丢包，红 = 断网）。
- **掉线与重连记录**：WAN 每一次断开和恢复的时间。
- **测速**：由路由器发起（Cloudflare 或 Speedtest.net），约 20～30 秒，会短暂占满带宽，每人每分钟一次。历史结果都会保留。

### 6.4 设备

- **自动识别**：根据 MAC 厂商（离线 OUI 库）、DHCP 主机名、mDNS / 网页探测，判断品牌、类型（手机、电脑、电视、摄像头、NAS、虚拟机……）和系统。随机 MAC 会标注出来。
- **PVE 虚拟机**：连接 Proxmox VE（只读 API Token）后，虚拟机显示它在 PVE 里的名称，并带「PVE 虚拟机 #编号」标签。
- **别名与备注**：显示名称以你起的别名为准，全面板统一（转发、管控、搜索都会显示）。名字里可以用撇号、大小写等任意字符。
- **在线判断**：路由器每 30 秒主动确认空闲设备是否还在（重新 ARP），只有真正应答才算在线；超过 90 秒未确认显示「已断开」，超过「离开判定时间」（默认 10 分钟）记一次「离开网络」，回来时记「回到网络」并附离开时长。
- **静态 IP 绑定**：给设备固定 IP（写入 dhcp host）。普通管理员只能管理自己创建的绑定，受配额限制。

### 6.5 设备画像

在设备详情页：

- **实时网速**：每 2 秒采样。
- **流量趋势**与**时段分布**（一周 × 24 小时热力图）。
- **流量去向**：按内容大类 → 服务 → 平台（所属公司）逐级下钻，例如「视频 → 抖音 → 字节跳动」。规则来自 blackmatrix7 规则库，并补充了 AI 等新平台，约 290 个服务，每 72 小时自动更新。
- **访问目标所在国家 / 地区**、**一天中的活跃时段**。
- **请求了哪些内容**：DNS 请求与流量合并统计。
- **连接目标**：按流量排序；规则库认不出的目标可以点「模拟访问」，路由器会读取证书、网页标题和反向解析来判断它是什么（标注「模拟判定」）。

### 6.6 流量统计与全球流量

- **设备排行**（下载 / 上传）、**全家流量去向**、**流量随时间变化**。
- **全球流量**：从家出发的「飞线」地图，按国家与城市统计流量。Cloudflare、Akamai 等 anycast CDN 计为本地。地图以太平洋为中心（适合新西兰 / 亚太用户）。24 小时 / 7 天 / 30 天的数据由后台预先计算，打开即看。

### 6.7 DNS 与 NextDNS

- **数据来源**可选：路由器自己的 dnsmasq 查询日志（默认，零依赖），或 NextDNS API（需要 API Key）。
- 查询趋势、拦截原因、被拦截最多 / 查询最多的域名、每台设备的查询（NextDNS 视角）、解析去向国家、协议分布、最近的查询记录。

### 6.8 端口转发

**新增转发**

- **内网设备**可搜索（名称、IP、MAC、厂商、类型、备注、PVE 标签），也可以直接输入 IP。
- **端口检查**：实时检查端口是否与其他转发、路由器自身正在监听的服务、面板端口冲突；是否在你被授权的端口段内；并建议可用的端口。
- **多 WAN**：可以把转发绑定到某个 WAN 口（`extra -i <设备>`）。
- **来源限制**
  - **限制来源**（推荐）：只允许指定国家 / 地区（如只允许新西兰、中国），或指定 IP / 网段；地区数据来自离线 IP 库，生成为 ipset。
  - **所有人**：对全世界开放。
  - **黑名单**：两种模式下都可以额外拒绝某些 IP / 网段。
- 写入后的规则是标准的 OpenWrt `firewall` redirect，备注里带结构化信息（创建者、设备、用途），LuCI 里同样可见。

**用量与连接分析**（列表里的「24h 用量」，或转发详情 →「查看流量与连接记录」）

- **转发后面运行的服务**：路由器主动连一下目标端口来识别，例如：
  - `SSH · OpenSSH_10.0`
  - `HTTPS · openresty`
  - `FTP · SmbFTPD`
  - `HTTP · nginx「飞牛 fnOS」`
  - RDP、VNC、MySQL、Redis、Telnet 等

  目标离线或端口没开，也会直接提示。
- **用量**：外部 → 设备、设备 → 外部分别统计；24 小时 / 7 天 / 30 天，每小时（或每天）一个点。
- **谁连了它**：每个来源 IP 的国家、城市、运营商（ASN）、连接次数、流量、会话时长、最后一次出现时间，以及自动判定：

  | 判定 | 依据 |
  |---|---|
  | 正常使用 | 有长时间会话、持续在线，或有真实的数据交换 |
  | 大流量 | 单个连接传输超过 10 MB |
  | 暴力破解嫌疑 | SSH 上反复出现 1 分钟以内、15 KB 以下的短连接（像在一次次试密码） |
  | 扫描 / 探测 | 只连接、不交换数据（少于 600 字节） |
  | 扫描机构 | Censys、Shodan、Shadowserver 等全网测绘机构的 ASN |

- **正在连接**：当前在线的每个连接（谁、什么时候开始、传了多少）。
- **最近连接**：最近 150 个连接，每个都标注类型（探测 / 短连接 / 会话 / 长会话 / 大流量）。
- **来源地区**：按国家统计。
- **自动提示**
  - 这段时间有多少连接是扫描。
  - 疑似暴力破解的 IP。
  - 暴露了高风险服务时给出建议（Telnet、FTP、数据库、Redis、远程桌面、VNC、明文网页；SSH 要关闭密码登录）。
  - 如果前面挂着 Cloudflare，提示真实访客 IP 要去网站日志里看。

> 统计范围：只统计配置为端口转发的入站连接。UPnP 自动映射、以及转发到路由器自身的规则不在其中。

### 6.9 设备管控

在「设备」里点开任意设备 →「访问控制」：

- **一键断网**。
- **黑名单 / 白名单**：按服务（如「抖音」「游戏」）或域名限制，基于 DNS 解析结果动态生成 ipset。
- **定时断网**：按星期与时间段，例如工作日 22:00–07:00。
- **禁止访问路由器端口**：例如不让某台设备访问路由器的 SSH / LuCI。
- **强制使用路由器 DNS**：防止设备用自己的 DNS 绕过拦截。
- **断网时仍允许联网检测**：手机不会因为「无法连接互联网」反复切换网络。

所有管控生效后都会在「设备管控」页集中列出。

### 6.10 网络工具

| 工具 | 说明 |
|---|---|
| **路由追踪** | 类似 OpenTrace / NextTrace：ICMP / TCP / UDP 三种方式；每跳显示 IP、反向解析、国家 / 城市、ASN 与运营商、平均 / 最好 / 最差延迟、丢包；地图画出数据包走的路线。 |
| **TCP Ping** | 测某个地址的端口通不通、是被拒绝还是被丢弃、延迟多少。 |
| **DNS 查询对比** | 同一个域名同时问路由器、阿里、腾讯、Cloudflare、Google、Quad9（或自定义），对比结果与耗时，发现污染与拦截。 |
| **网站访问测试** | 从路由器打开一个网址，拆成 DNS、TCP 连接、TLS 握手、等待首字节、下载五段计时。 |
| **本机 ↔ 路由器测速** | 浏览器直接测当前设备到路由器的速度（Wi-Fi / 网线），无需安装任何软件。 |
| **iperf3 服务端** | 路由器临时当测速服务器 10 分钟（到时自动关闭，只对局域网开放），页面给出可复制的客户端命令，每次测试结果自动列出。 |
| **iperf3 客户端** | 由路由器向 NAS、电脑、虚拟机发起测试，可选方向、TCP / UDP、并发流。 |
| **定时监控** | 见下文。 |
| **局域网扫描** | 扫描整个网段（约 10 秒）：找出不走 DHCP 的静态 IP 设备、不回 ping 的「哑设备」，并探测 32 个常用端口（SSH、网页、SMB、NFS、打印机、摄像头、PVE、Home Assistant 等），网页类端口可直接点开。 |
| **抓包** | 见下文。 |
| **网络唤醒** | 向局域网设备发送 Magic Packet。 |
| **UPnP** | 开关 UPnP，查看并删除设备自动创建的映射。 |
| **自定义解析** | 让局域网设备把某个域名解析到指定 IP（如 `nas.home`）。 |

**定时监控**

- 支持 **Ping** 和 **TCP 连接**两种方式，间隔 1～60 分钟，每轮 3～30 次。
- TCP 方式每次都从**新的源端口**发起连接。如果线路上的负载均衡路径有一条坏了，会表现为固定比例的连接失败，而这种问题 ping 往往看不出来。
- 连续两次异常（不通、丢包或延迟超过阈值）就通过告警渠道通知，恢复时也会通知并附异常持续时间。
- 数据保留 30 天，有 6 小时 / 24 小时 / 7 天 / 30 天的延迟与失败率曲线，可**导出 CSV**（适合附在给运营商的工单里）。
- 内置模板：Telegram 新加坡 / 迈阿密、Cloudflare、阿里 DNS、AWS 新加坡 / 悉尼。

**抓包**

- **选择接口**，页面会提示每个接口能看到什么：
  - **局域网接口**：每台设备自己的 IP（NAT 之前），排查某台设备用这个。
  - **外网接口**：运营商线路上的真实收发，排查国际线路用这个。
  - **全部接口**。
- **过滤条件**：设备 / IP、端口、协议（TCP / UDP / DNS / ICMP），也可以直接写 tcpdump 的 BPF 表达式（会先编译检查，写错会直接提示）。
- **抓包设置**
  - 最长时间：30 秒 ~ 30 分钟。
  - 文件上限：10 ~ 200 MB。
  - 「只抓包头」：保护隐私，文件也更小。
  - 排除面板自己的流量。
- **自动分析**：像 Wireshark 的「专家信息」一样直接给结论。
  - **TCP 健康**：握手成功率、握手失败（SYN 无应答）、握手延迟中位数和 P95、重传率、RST 重置、零窗口、重复 ACK、MSS。
  - **DNS**：查询数、平均和 P95 耗时、失败（SERVFAIL / REFUSED）、无应答、慢查询、查询最多的域名、使用了哪些 DNS 服务器。
  - **TLS 域名**（SNI）与 HTTP Host：看出访问了哪些网站。
  - **ICMP**：不可达（含「需要分片」MTU 问题）、TTL 超时。
  - **整体概况**：时间线（流量和重传）、协议与服务分布、主机排行、包大小分布。
  - **会话列表**：问题排在最前，可只看「有问题的」。
- **下载 pcap**：可以用 Wireshark 打开。
- 抓包能看到通信内容，所以是**单独的权限**；开始、下载、删除都会记入审计。抓包文件保存在路由器内存里（最多 12 个，共 600 MB），路由器重启或面板升级后清空，重要的请及时下载。

### 6.11 系统维护

- **硬件**：CPU（负载、核数）、内存、磁盘、温度（虚拟机通常没有温度传感器）、连接数。
- **依赖组件**：见第 5 节。
- **插件服务**：开关常见的 iStore / OpenWrt 插件（关键服务会提示风险）。
- **系统日志**：`logread` / `dmesg`，可搜索。
- **重启**与**定时重启**（按星期 + 时间，写入 crontab）。
- **配置备份与还原**：`sysupgrade -b`，包含 /etc 下全部配置（含密码、密钥）；还原前会先列出备份内容供确认。仅超级管理员。

### 6.12 告警推送

- **渠道**：Server 酱、Telegram Bot（可以添加多个；地址在界面和审计中打码）。
- **规则**
  - 新设备加入。
  - WAN 掉线超过 N 分钟。
  - 指定设备离线超过 N 分钟（例如监控 NAS、摄像头）。
  - 某设备每小时流量超过 N MB。
  - 面板被拒绝访问（有人试图从不允许的地方登录）。
  - 有待审批的操作。
  - 定时监控异常 / 恢复。
- **免打扰时段**：紧急告警（如 WAN 掉线）不受限制。
- **发送记录**：每一条告警发到了哪里、成功还是失败。
- 告警标题以你设置的面板名称开头，例如「【我家的网络】监控异常：……」。

### 6.13 系统设置

- **面板名称与副标题**。
- **敏感操作二次确认**：勾选哪些操作需要超级管理员批准（如开关插件、重启、端口转发、设备管控……）。
- **日志保留与判定**
  - 审计默认 365 天，访问记录 90 天。
  - 流量明细默认 7 天，总占用上限 1 GB（超出时从最旧的明细开始删）。
  - 设备离开判定时间默认 10 分钟。
- **路由器 Agent**：连接状态与版本。
- **IP 离线库**：DB-IP Lite（City + ASN），每月自动更新。
- **内容识别规则库**：版本与更新间隔。
- **NextDNS**：API Key 与 Profile。
- **Proxmox VE**：地址、只读 Token、证书指纹。
- **版本与更新**：GitHub 仓库地址；每 12 小时检查一次新版本，只提示、不自动安装。

所有设置的修改都会记入审计，并可还原。

## 7. 多管理员与权限

### 7.1 角色

- **超级管理员**：拥有全部权限，管理用户、审批、审计、访问记录、告警、访问控制、系统设置。
- **普通管理员**：由超级管理员创建，按需授予下列权限。普通管理员之间互相看不到、改不了对方创建的内容（转发、静态绑定、管控）。

### 7.2 权限表

### 7.3 配额与端口段授权

- **配额**：每个管理员最多可建多少条端口转发（默认 5）、多少条静态绑定（默认 10），-1 为不限。
- **端口段授权**：给某个管理员分配可用的公网端口段（可按 WAN 口）和可转发到的内网 IP 段，例如「8000–8010 → 192.168.1.100–192.168.1.120」。不同管理员的端口段互斥；别人的端口段对其他人（包括未受限的管理员）保留。未设置则不限制。

### 7.4 审批

在「系统设置 → 敏感操作二次确认」中勾选的操作，普通管理员提交后进入**审批队列**，超级管理员批准后才真正执行。管理员可以在「我的申请」里查看进度。待审批时可以推送告警。

### 7.5 操作审计与还原

每一条修改都记录：时间、管理员、来源 IP、操作、对象、摘要、**原值与新值**（并排对比），以及是否经过审批。端口转发、静态绑定、设备管控、设置等支持**一键还原**；还原本身也会被审计。

## 8. 安全设计

- **HTTPS**
  - 默认使用本地 CA 签发的证书。CA 带名称约束，只能签局域网地址和 `.lan` / `.local` / `.home.arpa` 这类本地域名。
  - 服务器证书有效期 397 天，路由器 IP 变化时自动重签。
  - 也可以改用你自己的证书，或关闭 TLS、放在反向代理之后。
- **面板访问控制**（决定谁能打开登录页）
  - **内网**：按设备 MAC 设白名单或黑名单。
  - **公网**：按国家 / 地区（基于服务器看到的来源 IP 和离线库）。
  - **IP 白名单 / 黑名单**：黑名单优先；白名单可跳过地区与设备检查。
  - **前端 IP 检查**（可选）：浏览器向 ip.sb 查询自己的出口 IP 并上报，用于发现分流代理。
  - **浏览器时区校验**：登录时比较浏览器时区与 IP 所在时区。
  - **救急**：被拒绝的访问会看到「拒绝访问」页面，并记入访问记录。把自己锁在外面时，可以在 LuCI 里「重置访问控制」。
- **访问记录**：每次打开面板都会记录访问时间、访问者本机时间与时区、IP、ASN、运营商、浏览器。时区不一致或出口 IP 不一致的会被标出。
- **登录保护**：失败次数限速、会话超时、CSRF 校验、`HttpOnly + Secure` Cookie、严格的 CSP。
- **Agent**：每个请求都有 HMAC 签名并防重放；默认只监听本机地址；VPS 模式下可开 HTTPS 和来源白名单，面板用证书指纹固定连接。
- **输入安全**：所有路由器命令都以参数数组方式执行，从不经过 shell；目标地址、端口、过滤表达式都有严格校验。
- **敏感信息**：NextDNS Key、PVE Token、告警地址在界面与审计中打码，只存在面板数据库里。

## 9. Wharf 会改动路由器的哪些地方

Wharf 只在你使用对应功能时才做改动，并尽量使用标准配置。

| 改动 | 位置 | 何时 | 卸载时 |
|---|---|---|---|
| 端口转发 | `/etc/config/firewall` 的 redirect（`owpr_*`）+ ipset（`owps_*`）；元数据 `/etc/config/owpfwd` | 新增转发 | 保留（它们是你的规则） |
| 设备管控 | `/etc/config/owpdev`；iptables 链 `owp_pol` / `owp_polin` / `owp_dns`；ipset `owp_p[bw]_*` | 设置管控 | 链和 ipset 清除 |
| 流量计数 | iptables 链 `owp_acct`；ipset `owp_up` / `owp_dn` | 启动 agent | 清除 |
| DNS 查询日志 | dnsmasq `logqueries` + `logfacility=/var/log/owp-dns.log` | 启动 agent（首次） | 恢复 |
| 面板 / agent 的 WAN 放行 | firewall rule `owp_panel` / `owp_agent` | 仅当你在 LuCI 勾选「允许外网访问」 | 删除 |
| 静态绑定、自定义解析 | `/etc/config/dhcp`（host / domain 段） | 使用时 | 保留 |
| 定时重启 | root crontab（带 `# owp-reboot` 标记） | 设置时 | 保留（可在面板关闭） |
| 依赖组件 | opkg 软件包，记录在 `/etc/wharf-deps.list` | 你在面板里安装时 | 面板装的会移除（见第 5 节） |
| 连接字节统计 | `/etc/sysctl.d/90-wharf.conf` | 你在面板里开启时 | 删除 |
| 面板数据 | `owp.main.data_dir`（数据库、证书、离线库、规则库） | 运行时 | 保留，可手动删除 |

**Wharf 不会做的事**：
- 不重启网络或 WAN。
- 不修改 LAN 网段、WAN 拨号和 Wi-Fi 配置。
- 不升级固件或内核。
- 不动你已有的其他插件配置。

## 11. 命令行与 LuCI 页面

**LuCI：服务 → Wharf 码头**
- 开关 Agent / 面板，设置端口、是否允许外网访问。
- 查看面板入口（局域网 / 公网地址），复制 Agent 密钥（VPS 模式用）。
- 重置超级管理员密码、重置面板访问控制（把自己锁在外面时用）。

**命令行（在路由器上，root）**

```sh
P="/usr/bin/owp-panel -config /var/etc/owp/panel.json"

$P reset-super                         # 生成新的超级管理员密码
$P reset-access                        # 清空面板访问控制
$P setting nextdns.api_key <KEY>       # 写入设置（敏感设置只在数据库中）
$P monitor-add "Telegram 新加坡" 91.108.56.130 tcp 443 20 5 10
                                       # 名称 目标 icmp|tcp 端口 次数 间隔(分) 丢包告警%
$P monitor-export > monitors.csv       # 导出所有监控结果

/etc/init.d/owp restart                # 重启 agent 与面板
logread | grep -E "owp|wharf"          # 查看日志
```

## 12. 常见问题

**打开面板提示「无法连接 / 不安全」**
按 4.3 安装证书。iPhone 主屏幕上的 Web App 不允许跳过证书警告，必须安装证书。

**面板里看不到流量去向**
到「系统维护 → 依赖组件」确认 conntrack、连接字节统计、ipset 都已就绪。数据按分钟汇总，刚安装时要等几分钟。

**设备显示「未知设备」**
没有 DHCP 主机名、厂商也认不出时会这样。在设备详情里起个别名；PVE 虚拟机可以连接 PVE 自动获取名称。

**手机明明离开了还显示在线**
手机息屏后 Wi-Fi 会休眠。Wharf 在 90 秒未确认后显示「已断开」，超过「离开判定时间」（默认 10 分钟）才记为离开，避免反复横跳。可以在设置里调整。

**端口转发的「谁连了它」是空的**
逐连接记录从 0.15 版开始采集，而且只统计端口转发的入站连接。端口没人访问时就是空的；小时级用量是历史数据，可以直接看。

**网络很卡，怎么排查**
1. 用「网络」页看 WAN 延迟和掉线记录。
2. 用「路由追踪」看慢在哪一跳。
3. 用 TCP 方式的「定时监控」长期观察目标；固定比例的连接失败说明线路有问题。
4. 用「抓包」在外网接口抓一段，看握手失败和重传。
5. 导出监控 CSV 和 pcap 附给运营商。

作者就是用这套流程，向运营商证明了一条国际线路的故障。

**卸载**
`opkg remove luci-app-wharf`。会清除 Wharf 的防火墙链、ipset、dnsmasq 日志设置和面板装的依赖组件；你的端口转发规则和面板数据会保留（数据目录可手动删除）。
